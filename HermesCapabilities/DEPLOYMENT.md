# 🚀 DEPLOYMENT.md — Keys & deployment of capability agents

> Complete reference of environment variables for deploying a
> capability agent (AREV email pipeline) — from your **local bashrc** down to
> the **container runtime**. No secret value is ever documented
> here — only the **names**.

---

## 1. The 3 levels of variables

| Level | Where | Role |
|---|---|---|
| **A. Local bashrc** (`~/.bashrc`, prefix `VPS_`) | Your PC (WSL) | Source of truth for secrets — used by local tests and the SQL runner |
| **B. `HermesConfig/clients/<slug>/client.env`** (600, on the VPS) | VPS | Client secrets + config — referenced by the compose `env_file`, **never committed** |
| **C. Container runtime** | VPS | The same variables, injected into the Hermes process |

**Flow**: local bashrc → (manual/ssh copy) → `client.env` → compose
(`env_file`) → container. The SQL runner automatically generates
`CLIENT_RPC_SECRET` into `client.env`.

## 2. Complete table of variables

### Email reception (C1 `email-gmail`)

| Var | Level B/C | Usage |
|---|---|---|
| `VPS_GMAIL_RECEPTION_IMAP_ADRESS` | ✅ | Gmail mailbox (`REDACTED_EMAIL`) — historical spelling kept |
| `VPS_GMAIL_RECEPTION_IMAP_MDP` | ✅ | IMAP **app password** (Gmail 2FA required, IMAP enabled) |

> ⚠️ The OAuth/refresh token is **not** used (D13 — refresh expires after 7d in
> Testing mode). The `gmail-oauth-setup.sh` helper remains a plan B tool.

### Embeddings (C4 `rag-embeddings`)

| Var | Usage |
|---|---|
| `VPS_GEMINI_API_KEY` | Gemini key (embeddings `text-embedding-004` 768d + OCR vision #1 + SLM Flash adapter) |

### OCR (C3 `doc-ocr`)

| Var | Usage |
|---|---|
| `VPS_GEMINI_API_KEY` | Vision #1 (same key as C4) |
| `VPS_OPEN_ROUTER_API_KEY` | Vision #2 (OpenRouter, model `OCR_OPENROUTER_MODEL=openai/gpt-4o-mini`) |

### RAG / DB (C5 `rag-supabase` + RPC)

| Var | Usage |
|---|---|
| `VPS_SUPERBASE_VPS_DB_URL` | **Admin** connection string (pooler 6543) — SQL runner **only** (never to the container) |
| `VPS_SUPERBASE_VPS_DB_PROJECT_URL` | REST URL of the Supabase project — container (supabase MCP) |
| `VPS_SUPERBASE_VPS_DB_RPC_KEY` | **Publishable** key — container (never the service key, D8-v3) |

### GED R2 (archiving raw emails)

| Var | Usage |
|---|---|
| `VPS_GED_CLOUDFLARE_S3_EU_ENDPOINT` | R2 endpoint (`https://…eu.r2.cloudflarestorage.com`) |
| `VPS_GED_CLOUDFLARE_BUCKET_NAME` | Bucket (e.g. `suren-saas-ged`) |
| `VPS_GED_CLOUDFLARE_ACCESS_KEY_ID` | R2 access key |
| `VPS_GED_CLOUDFLARE_SECRET_ACCESS_KEY` | R2 secret (SigV4) |
| `VPS_GED_CLOUDFLARE_TOKEN` | Cloudflare **REST** API token — ⚠️ **not used** by the S3 API (R2 rejects x-amz-security-token, checked 01/09). Kept for REST admin |

### Auto-generated (do NOT create by hand)

| Var | Generated by | Usage |
|---|---|---|
| `CLIENT_RPC_SECRET` | Runner `supabase-sql.sh` (→ `client.env` 600) | Slug RPC secret — required by **all** generic RPCs (D8-v3) |
| `CLIENT_SLUG` | `client.env` (e.g. `arev`) | Multi-tenant discriminator — R2 subfolder, RPCs |

### LLM model (Hermes native)

| Var | Usage |
|---|---|
| `DEEPSEEK_API_KEY` | ⚠️ **Native Hermes name** (deepseek provider) — do NOT rename to `VPS_*` in client.env, otherwise Hermes won't see the key. If you want the prefixed source, alias at spawn time (`DEEPSEEK_API_KEY=${VPS_DEEP_SEEK_API_KEY}`) — decision to be validated |

## 3. client.env variables — complete model (`clients/arev/client.env`)

```bash
CLIENT_SLUG=arev
CLIENT_NAME="AREV Travaux"

# Telegram
TELEGRAM_BOT_TOKEN=<dedicated bot from @BotFather>
TELEGRAM_ALLOWED_USERS=<team IDs>

# Model (native Hermes name — see note §2)
DEEPSEEK_API_KEY=<clé deepseek>

# Email C1
VPS_GMAIL_RECEPTION_IMAP_ADRESS=REDACTED_EMAIL
VPS_GMAIL_RECEPTION_IMAP_MDP=<app password>

# Gemini (C3 vision #1 + C4 embeddings + Flash adapter)
VPS_GEMINI_API_KEY=<clé gemini valide>

# OpenRouter (C3 vision #2)
VPS_OPEN_ROUTER_API_KEY=<clé openrouter>

# Supabase C5 (REST)
VPS_SUPERBASE_VPS_DB_PROJECT_URL=https://<ref>.supabase.co
VPS_SUPERBASE_VPS_DB_RPC_KEY=<publishable key>

# GED R2 (raw archiving)
VPS_GED_CLOUDFLARE_S3_EU_ENDPOINT=https://<account>.eu.r2.cloudflarestorage.com
VPS_GED_CLOUDFLARE_BUCKET_NAME=<bucket>
VPS_GED_CLOUDFLARE_ACCESS_KEY_ID=<key id>
VPS_GED_CLOUDFLARE_SECRET_ACCESS_KEY=<secret>
VPS_GED_CLOUDFLARE_TOKEN=<token REST — non utilisé par S3>

# Generated by the runner (do not create by hand)
CLIENT_RPC_SECRET=<generated by supabase-sql.sh>
```

> `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USERS`, `CLIENT_SLUG`,
> `CLIENT_NAME`, `HERMES_MODEL_*`: unchanged (HermesConfig v2).

## 4. Deploying the email pipeline (M2.6 — checklist)

```bash
# 0. Local bashrc: all VPS_* present (local tests green)
# 1. Client secrets on the VPS
ssh nemo 'vim /home/admin/hermes-fleet/HermesConfig/clients/arev/client.env'  # §3 + CLIENT_RPC_SECRET
# 2. Sync of subprojects (git mirror)
rsync -av --exclude 'instances/' --exclude '*.env' \
  ~/dev/VPS/HermesConfig/ ~/dev/VPS/HermesCapabilities/ nemo:/tmp/sync/
ssh nemo 'sudo rsync -a /tmp/sync/HermesConfig/ /home/admin/hermes-fleet/HermesConfig/ \
  && sudo rsync -a /tmp/sync/HermesCapabilities/ /home/admin/hermes-fleet/HermesCapabilities/ \
  && sudo rm -rf /tmp/sync'
# 3. SQL (if new migrations) — runner generates CLIENT_RPC_SECRET if needed
ssh nemo 'cd /home/admin/hermes-fleet/HermesCapabilities && sudo ./scripts/supabase-sql.sh arev all --smoke --yes'
# 4. Attach of capabilities (compose re-rendered if spawn v2.1)
ssh nemo 'cd /home/admin/hermes-fleet/HermesCapabilities && sudo ./scripts/capability-attach.sh arev email-gmail email-processing doc-ocr rag-embeddings rag-supabase analysis-facturation ged-r2 --dry-run'
ssh nemo 'cd /home/admin/hermes-fleet/HermesCapabilities && sudo ./scripts/capability-attach.sh arev email-gmail email-processing doc-ocr rag-embeddings rag-supabase analysis-facturation ged-r2'
# 5. Validation
ssh nemo 'cd /home/admin/hermes-fleet/HermesCapabilities && sudo ./scripts/supabase-sql.sh arev status'
ssh nemo 'sudo /home/admin/hermes-fleet/HermesConfig/scripts/audit-hermes-pro.sh arev'
# → send a real email to REDACTED_EMAIL (with a scanned invoice attachment)
# → check: spool, R2 (GED), cap_email_chains/cap_emails, cap_documents, cap_factures (extracted status)
```

| OpenRouter vision | requests | ~10/day (low-cost model) |
| R2 | storage + A/B ops | a few MB/day |
| Supabase | rows + pgvector | negligible at first |
